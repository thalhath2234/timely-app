# Phase 6 runtime overrides (agent bots)

These two are runtime overrides: no vendored file is edited and the patch-point budget (zero today, cap five) is untouched. They belong in the "Runtime overrides" table of `.hermes-sync/patches.md` (R9 and R10, next to R1 to R8); that file is outside this work package, so the rows are kept here until they are copied over (plan 7.10: "It is listed in `patches.md` as a runtime override").

| Override | Hermes symbol | Why | Applied by | Test |

| R9 empty upstream `cronjob` toolset | `toolsets.TOOLSETS["cronjob"]["tools"]` (set to `[]`), `toolsets._resolve_toolset_memo` (cleared) | The managed floor `agent.disabled_toolsets` lists `cronjob` (upstream scheduling is never offered), and `model_tools` subtracts a disabled toolset **by tool name**. The static `cronjob` toolset lists `cronjob_manage`, which is also the name of Timely's shim (toolset `timely_schedule`, plan 7.10), so the floor would remove the shim from every chat. With the static list empty the subtraction removes nothing and the upstream toolset still offers no tool if anything enabled it (`run.start` refuses `cronjob` anyway, `config_render.NEVER_TOOLSETS`). | `timely_agent/plugins/timely_bot/cronjob_shim.py` `neutralise_upstream_toolset`, called by `ensure()` after plugin discovery (`worker.on_hello`); the self-test (`bot_tools`) checks `cronjob_manage` is still offered for `enabled_toolsets=["timely_schedule"]` with the managed `disabled_toolsets` | `tests/contract/test_bots_run.py::test_a_chat_can_schedule_only_through_a_proposal`, `::test_the_self_test_pins_the_cronjob_manage_handler_to_the_timely_shim` |
| R10 `cronjob_manage` shim | `tools.registry.registry.register(name="cronjob_manage", override=True)` through `PluginContext.register_tool(override=True)`; granted by `plugins.entries.timely_bot.allow_tool_override: true` in the managed config for `timely_bot` only | Upstream's `tools/cronjob_tools.py` registers `cronjob_manage` at import, whatever the toolset config says; a plugin cannot shadow a built-in name without `override=True` plus the grant. The shim turns create, update, pause, resume and remove into `create_bot` / `update_bot` proposals, so nothing is scheduled in Hermes. If upstream's import re-registers the name after plugin discovery, `ensure()` registers the shim again directly. The tool policy keys on the owner: `timely_gate` allows `cronjob_manage` only while the registry's handler module is `timely_agent.plugins.timely_bot.cronjob_shim`, and blocks it otherwise (and always in a bot tick). | `timely_agent/plugins/timely_bot/cronjob_shim.py` (`register`, `ensure`); `timely_agent/plugins/timely_gate/__init__.py` (`_cronjob_verdict`) | `tests/test_bot_units.py::test_ensure_re_registers_the_shim_when_upstream_took_the_name_back`, `::test_the_gate_allows_cronjob_manage_only_when_the_shim_owns_it`, the self-test check `bot_tools` |
