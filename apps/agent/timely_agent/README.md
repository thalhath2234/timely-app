# timely_agent

Timely's host package around the vendored Hermes copy in `../hermes` (plan `docs/plans/2026-11-08-timely-agent-from-hermes.md`, sections 3.2-3.4, 4.4, 5.1, 6, 9.1). The Go API runs it; the wire contract is `../PROTOCOL.md`.

| Module | Job |
| --- | --- |
| `boot.py` | Entry point (`python -I boot.py worker|prepare|render-account`). Moves the protocol to private descriptors before any Hermes import, sets `sys.path = [hermes, apps/agent, site-packages]`. |
| `worker.py` | The per-account worker: hello/ready, runs, ping/heartbeat, shutdown, stdin-EOF lifeline. |
| `protocol.py` | Line framing, message validation, account check, error codes, worker-to-Go request waits. |
| `env_check.py` | The environment allowlist and refusals (plan 6.4); runs before Hermes is imported. |
| `paths.py` | The `<data>/agent` layout (plan 6.1) and the account folder name. |
| `cli.py` | `prepare` (API start) and `render-account` (before each spawn). |
| `config_render.py` | Managed floors, account `config.yaml`, `SOUL.md`, MCP entry rules, the canary. |
| `seed.py` | Seed tree of reviewed bundled skills plus overrides, and the read-only Timely skills copy (plan 9.1). Stdlib git tree ids. |
| `install_guard.py` | Runtime override R1: no package installs in a worker (`../.hermes-sync/patches.md`). |
| `plugin_dist.py` | Serves the Timely plugins to Hermes' `hermes_agent.plugins` entry-point group: every folder under `plugins/` whose `__init__.py` defines `register`. |
| `plugins/` | `timely_gate` (tool policy, propose-alone, end of turn), `timely_tools` (Timely tools over `tool.call`; a result Go marks `outside` reaches the model as untrusted data, as Hermes marks web results: `untrusted.py`, Q-3.9), `timely_learning` (read-only Timely skills, the learning policy: block, stage or apply; past-chat search, whose hits from a tainted chat are untrusted data too; taint), `timely_bot` (phase 6 stub). |
| `learning/` | Phase 3 adapters around Hermes' learning (plan 9b): `rules` (the policy decision), `staging`, `feed` (`learning` messages), `counters`, `passes` (`busy.learning`), `curator`, `api` (Go's `learning.*` requests), `files` (home layout readers). |
| `selftest.py` | The checks in `ready.self_test`. |
| `run_chat.py` | One chat turn on `AIAgent.run_conversation`: the Timely block as `ephemeral_system_prompt`, Hermes' own turn limit, coalesced `delta` events, end of turn after a proposal, history seeds into `state.db`, a per-conversation agent cache. |
| `bridge.py`, `policy.py` | Run context shared with the plugins (batches, taint, end of turn, the Timely tool specs, `tool_call` for Go-run backends) and the per-conversation session state that outlives a run; tool name lists and taint sources. |

Tests: `../tests` (`make agent-test`); they start real workers against a stub OpenAI-compatible model. `../tests/record_events.py --out <dir>` records the worker event fixtures for the Go engine (`make agent-record-fixtures`), and `../tests/measure_prompt.py` reruns the phase 2 measurements below.

## Phase 1 decisions and findings (Hermes v0.23.0)

- **Plugin loading (plan 4.3).** Entry points, not plugin folders: `plugin_dist.py` registers an in-memory distribution on `sys.meta_path` whose `entry_points.txt` names `timely_agent.plugins.<name>:register` in the `hermes_agent.plugins` group. Nothing is copied into account homes or pip-installed, and `plugins.enabled` in the managed config still decides what loads. The plugins live in `timely_agent/plugins/`, not `apps/agent/plugins/`: a top-level `plugins` package beside `hermes/` would collide with Hermes' own `plugins` package on `sys.path`.
- **Managed overlay is not seen by every reader (plan 6.3).** `load_config()` deep-merges `HERMES_MANAGED_DIR/config.yaml` on top, but `agent.skill_utils` reads `config.yaml` raw for `skills.external_dirs` and `skills.disabled`. So the account `config.yaml` repeats every managed floor, and the canary checks the managed file, the merged config and the raw skill reader.
- **Floor keys as v0.23.0 names them** (`config_render.managed_floors()`). `plugins.enabled` (the four Timely plugins), `plugins.disabled` (every bundled `kind: platform` manifest plus `image_gen/*`, `video_gen/*` and `dashboard_auth/*`, read from the snapshot), `plugins.isolation: in_process`, `plugins.auto_apply: false`, `plugins.auto_update_check_hours: 0`, `plugins.entries.timely_bot.allow_tool_override`, `security.allow_private_urls: false`, `security.fake_ip_ranges: []`, `security.allow_lazy_installs: false`, `security.redact_secrets/protected_instruction_files: true`, `telemetry.shared_metrics.enabled/send: false`, `approvals.mode: manual` (a valid mode), `approvals.cron_mode/unattended_mode/single_query_mode: deny`, `skills.inline_shell: false`, `skills.guard_agent_created: true`, `skills.project_discovery: false`, `skills.trusted_project_dirs: []`, `skills.external_dirs`, `skills.create_dir: ''`, `web.keyless_fallback/keyless_rescue: false`, `browser.executable_path`, `browser.use_real_profile: false`, `browser.auto_local_for_private_urls: false`, `lsp.install_strategy: manual` (no `go install` / `npm install` of a language server), `memory.provider: ''`, `display.language: en`, `auth.adopt_external_logins: false` (Hermes would otherwise borrow the host user's Codex and Claude Code logins), `cron.allow_agent_scheduling: false`, `hooks_auto_accept: false`, `tools.tool_search.enabled: off` (until the phase 2 measurement), `tools.connectors.enabled: false`, `agent.disabled_toolsets` (`NEVER_TOOLSETS`; AIAgent does not read this key, so `run_chat.build_agent` passes the same list as `disabled_toolsets` and `run.start` refuses those toolsets and `hermes-*` bundles), `auxiliary.title_generation.enabled: false` and `command_allowlist: []` (no config can pre-approve a call). There is no browser "auto-download" key: Chromium arrives through Hermes' package manager, which the install guard and `allow_lazy_installs: false` block. Bundled platform plugins register whatever `plugins.enabled` says, and only `plugins.disabled` wins, so the managed config lists each one there; the self-test fails on any enabled platform plugin or imported adapter module, the worker never starts the gateway and the environment carries no platform tokens.
- **Locales.** `display.language: en` is pinned and `HERMES_LANGUAGE` / `HERMES_BUNDLED_LOCALES` are refused, so the English-only copy is enough (sync finding 6).
- **Account folder name.** `account-` + hex of the first 12 bytes of sha256(uid), 24 hex characters, exactly as `portability/service.go`; the plan's `sha256(uid)[:12]` means bytes.
- **Essential skills.** Hermes never lets `hermes-agent` be disabled (`ESSENTIAL_SKILLS`), and `skills-reviewed.json` marks it `default: off`, so the seed tree leaves it out entirely; other `default: off` skills are seeded and listed in `skills.disabled`. The self-test fails if Hermes' essential list changes.
- **Gate ordering.** Hermes applies every plugin's `block`, whatever the order, so `timely_gate` lets `skill_manage` through without asking Go and `timely_learning` owns its policy.
- **Python.** uv-managed CPython 3.14.9 (the build Hermes pins in `pm/lock.json`), installed from Hermes' own `uv.lock` with `--no-install-project`.
- **Cost (this machine, warm).** Spawn to `ready` 1.0-1.2 s, including the Hermes import, plugin discovery, seeding 43 skills into a fresh home and the self-test.

## Phase 2 decisions and measurements (Hermes v0.23.0, stub model)

- **Timely block: `ephemeral_system_prompt` (plan 5.3, contract test 6).** Both candidates ran: two turns in one worker, a third in a fresh worker (agent rebuilt from `state.db`), a fourth with a changed block. Both keep the system message byte-identical across turns 1-3 and both start with the Timely identity (no "You are Hermes Agent"). Only `ephemeral_system_prompt` passes the fourth: Hermes stores the first turn's prompt (with `system_message` inside) in `state.db` and restores it verbatim on every later turn, so a changed `system_message` (a new catalog's write schemas, the Q-2.1 scope line) never reaches the conversation again. The ephemeral block is appended at API time, never stored, and the background review fork copies it (cache parity). `run_chat.SYSTEM_VIA = "ephemeral"`; the agent cache key includes the block's hash.
- **Persona (Q-2.6).** The default `SOUL.md` is Timely's identity ("You are Timely, the assistant inside the Timely app...") with tone only; scope and abilities stay in Go's block. Residual: Hermes always adds `HERMES_AGENT_HELP_GUIDANCE` (a pointer to Hermes' docs for "help with Hermes Agent itself"), with no config switch at v0.23.0; removing it needs a patch point. The managed floor `agent.environment_probe: false` keeps the host's toolchain (python, pip, uv) out of chat prompts.
- **Batch seam.** A tool handler gets only its arguments. `timely_tools` records each model response's tool calls from the `post_api_request` hook (`assistant_message`), before any of its tools runs, and finds its own call id in `tools.approval_context._approval_tool_call_id`. Hermes renames a reused call id (`call_1` -> `call_1_d2`, `agent_runtime_helpers._dedupe_tool_call_ids`) after the hook, so an unknown id falls back to the latest response holding that tool. Plugin tools run sequentially (they are not path-scoped, so Hermes never parallelizes them). Both seams are in contract test 7.
- **End of turn (Q-2.4).** After `end_turn`, a further tool call gets a soft interrupt with `tool_reason="timely_end_turn"`; Hermes then appends an empty assistant row, so the closing text is the last non-empty assistant text after the proposal. The interrupt is cleared before the next turn.
- **Q-2.3.** `DEFAULT_MAX_ITERATIONS` (30) is gone: empty `budgets` give Hermes' `agent.max_turns` through `resolve_turn_limit` (unlimited by default). A 32-iteration turn completes.
- **Streaming (Q-2.5).** `DeltaCoalescer`: 600 two-character chunks over about 1.3 s arrive as 27 `delta` events (three runs, at most 50 characters each), joined byte-exact, all before `run.done`; without coalescing that is 600 events.
- **Auxiliary credentials (plan 5.7, contract test 20).** Context compression is the one auxiliary call a phase 2 chat can make. With the run on stub A (`sk-run-A`) and `OPENAI_BASE_URL`/`OPENAI_API_KEY` pointing at stub B in the worker environment, an 8-turn conversation over a 64K window compacted, and every chat-completions request, summaries included, went to A with the run key; B got nothing; no connection left 127.0.0.1 (model metadata GETs may go without a key). Hermes' auto route takes the main provider and its credentials first (`agent/auxiliary_client.py` `_resolve_auto_route`). No provider keys are needed in the worker environment.
- **History seed.** Hermes stores only a turn's new messages, never a caller's `conversation_history`, so a phase-1 seed was lost after its turn. The worker now writes a seed into `state.db` when the session has no messages there and ignores it otherwise (`run.done.history_seeded`).

### tool_search off vs on (plan 1.4)

The 49 Timely specs (`../tests/fixtures/timely_tools.json`: the 47 Read tools from Go's catalog on 2026-11-09, `propose_changes`, `resolve_target`) with toolsets `timely`, `todo`, `skills`; `tools.tool_search.enabled` forced through `probe_boot --tool-search`. Request size at 4 bytes a token:

| `tool_search` | turn 1 request | turn 2 request | `tools` array | Timely tools listed | direct `get_task` call |
| --- | --- | --- | --- | --- | --- |
| off | 40,852 B (~10.2K tokens) | 40,968 B (~10.2K tokens) | 53 tools, 33,062 B | 49 | reaches Go as `tool.call` |
| on | 18,513 B (~4.6K tokens) | 18,627 B (~4.7K tokens) | 6 tools (3 bridge), 10,797 B | 0 | "Tool 'get_task' does not exist" |

Hermes defers every plugin tool behind `tool_search`/`tool_describe`/`tool_call` (`tools/tool_search.py` `is_deferrable_tool_name`), and `timely_gate` blocks those bridge names, so with it on no Timely tool is callable. The saving (~5.6K tokens a request) is also mostly prompt-cacheable, because the tools array is byte-stable per conversation. Decision: the managed floor stays `tools.tool_search.enabled: off`.

### context_engine (plan 2)

The bundled `plugins/context_engine` package ships no engine at v0.23.0: it only discovers `plugins/context_engine/<name>/` folders (none in the snapshot) and user plugins under `$HERMES_HOME/plugins` (refused by the self-test). `discover_context_engines()` returns `[]`, and the built-in `compressor` is the only engine. On a 10-turn stub conversation (each turn ~22 KB of unique text, 64K window, real usage reported) the compressor compacted at turns 6, 8 and 10, one summary side call each (42, 104 and 134 KB requests to the run's endpoint). Turn requests grew by about 45 KB a turn up to 205 KB (turn 5) and were 172 KB, 151 KB and 181 KB on the compacted turns instead of the about 250, 262 and 241 KB they would have reached. Verdict: nothing to adopt; the managed floor now pins `context.engine: compressor`, so no account config can select an engine Timely has not evaluated. `selftest.EXPECTED_PLUGINS` is unchanged. Re-run `measure_prompt.py context_engine` after a sync that adds an engine.

## Phase 3 decisions (Hermes v0.23.0, stub model)

- **Learning per run.** `flags.learning_writes` builds the conversation's agent with the learning pass (`skip_background_review` is its negation, and part of the agent cache key). A chat always has About you and Notes in its prompt (`skip_memory=False`, plan 9b.3): learning off, a Sensitive or Don't-learn chat and an answer-only turn stop the writes and the pass, not the reading. Hermes' own `write_approval` gate stays off in the account config: `timely_learning` decides each write (block on a strict threat-scan hit, stage when the chat is tainted, from a bot, an unattended memory patch/remove, or the skill-body rule matches; otherwise apply silently). The rule order and the facts it uses are `learning/rules.py`; contract test 9 (`tests/contract/test_c09_learning.py`) runs each case on a real worker.
- **The learning pass has no run.** Hermes forks the agent on a daemon thread after the turn (`agent/background_review.py`), copying the run thread's context. Inside the fork `bridge.current_run.get()` answers `None` (it checks Hermes' `background_review` write origin), so nothing there can end the finished run's turn, ask Go about a tool for it, or stream into it; the fork's hooks carry the conversation's session id, and `bridge.session_state(session_id)` gives the taint and flags. The fork has Hermes' tool whitelist (skills tools, `read_file`/`search_files`, `memory` when the memory review fired); `timely_gate` blocks the file tools there (no run), and the Timely skills stay read-only (contract test 16, both halves).
- **No separate learning model (Q-3.2).** `auxiliary.background_review` is never rendered, so the fork resolves the parent's runtime: the run's provider, model, `base_url` and key. Contract test `test_c09_learning_pass_uses_the_run_credentials` sends the pass to a stub with `OPENAI_BASE_URL`/`OPENAI_API_KEY` pointing at a second one: every request went to the run's endpoint with the run's key.
- **Counters file.** `<home>/.timely/counters.json` keeps `_iters_since_skill` and `_turns_since_memory` per conversation: written after each turn, when an agent leaves the cache (LRU, a changed config signature, a failed run, a settings change) and at shutdown; set on the next agent of that conversation. Two 6-tool turns fire one skill review, also across a worker restart (`tests/test_learning_worker.py`). After a staged foreground write the plugin resets the counter (Hermes resets it only for a call that runs), so a tainted chat does not re-run the review every turn.
- **Curator setting found.** Hermes' curator has no "never archive" switch: `apply_automatic_transitions` archives a curator-managed skill whose last activity is older than `curator.archive_after_days` (floored at 1, default 30). The account config sets it to 36,500 days, keeps `consolidate: false` (no LLM pass) and `stale_after_days: 14`. The worker's maintenance tick calls `maybe_run_curator` every 10 minutes while no run is live; Hermes' own gate runs a pass once a day (`interval_hours: 24`, and the first tick only seeds the clock). A 31-day-unused learned skill goes stale and stays (`test_curator_never_archives_a_31_day_unused_learned_skill`, with Hermes' default as the control, which archives it). No patch point.
- **The feed.** A change is reported once: the worker keeps a baseline of the home (ledger ids, MEMORY.md/USER.md entries, staged ids), saved in `.timely/feed-baseline.json` so a later worker reports what an earlier one did not (`catch_up` after `ready`; with no saved baseline the home at start is the baseline), and diffs after each run (after the last `delta`, before `run.done`) and when a learning pass ends (`background_review_callback`, and a watcher on the pass's run token, `_background_review_run.request_done`). Changes keep the chat that made them when chats overlap: a ledger entry names its conversation (`evidence.session_id`) and takes that conversation's run, origin and taint from its session state; each `memory` call that applies reports its own change from `timely_learning`'s hooks (`Feed.begin_memory_write` / `end_memory_write`), and a diff leaves memory alone while one is in flight.
- **Past-chat search.** `session_search` is a local allow in the gate and decided by `timely_learning`: refused without `flags.search_history`; `search_exclude` goes into `exclude_session_ids` (Hermes caps that list at 20, so `transform_tool_result` also drops excluded chats from results); reading an excluded chat by id and another profile's store are refused; a hit from `tainted_conversations`, or from a chat whose worker state holds taint (a chat running at the same time read a page after `run.start`), taints the session. `policy.TAINT_SOURCES` no longer lists `session_search` outright.
- **Plugin set from folders.** `plugin_dist.PLUGINS` is every package folder under `plugins/` with a `register` (phase 1 order first, then sorted); the managed `plugins.enabled`, the self-test's expected set and the entry points follow it. A new Timely plugin is a new folder.
- **Recorded fixtures.** `tests/record_events.py` adds `learning_skill_applied`, `learning_skill_staged` and `learning_memory_added`; `blocked_non_timely_tool` now uses `clarify` to reach Go's gate, because `session_search` is decided in the worker since phase 3.
